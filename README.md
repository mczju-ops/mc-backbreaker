# MC Backbreaker

模仿机械狂欢中的backbreaker

游戏名：史莱姆陷阱

作者：Yikuni

游戏说明：逃离邪恶的史莱姆，利用好友当作挡箭牌，建议人数：3-7人

## 游戏说明

游戏开始时，所有玩家被传送到房间中的指定位置（出生点，可配置）。

玩家之间无法进行pvp，游戏中不能跳跃；所有玩家的行走速度可配置，并获得饱和效果。

过一段时间，前面所述的指定位置出现中型史莱姆，这个史莱姆没有AI，无法被攻击。

史莱姆会追踪最近的玩家，并以一定的速度向最近的玩家移动。注意史莱姆不能浮空，不能穿模（需要绕开障碍物）

史莱姆距最近玩家一定距离时（可配置），会停下，并以一个动画向玩家头处飞去，并附在玩家头上，进一步降低玩家行走速度（可配置）。可配置附身爆炸倒计时，默认按每位玩家在整局内的实际持有时间累计：扔出后暂停，再次附身时继续，局内进入下一轮也不会清零，累计达到指定秒数即爆炸淘汰。关闭累计开关后，每次附身重新计时。倒计时设置为 0 或负数时禁用。

玩家可用右键将附在头上的史莱姆以一定速度扔出去，但只有史莱姆附身一定时间后才能扔出，扔出后玩家的行走速度恢复成初始设置。史莱姆落地后，会重新找当前最近的玩家，并持续刚才的步骤，一直追最近的玩家，直到追上

每一轮都有个boss条，用于显示倒计时，倒计时结束时，如果史莱姆已经附在玩家身上，则那个玩家爆炸（仅音效和粒子效果），并死亡，转换成旁观模式。如果没有附在玩家身上，则下次附身到玩家身上，玩家就死。

死一个玩家后，过5s倒计时，史莱姆会重置在出生点，并重新找最近的玩家。

重复若干轮后，直到最后剩余1人，那个人获胜。输出最终存活时间排名，不制作排行榜。

玩家中途退出，则视为死亡，直接进下一轮。

## 其它要求

史莱姆的移动可以设置成移动动画，每一tick计算下一tick移动到哪，中间可以用paper的api进行插值

游戏结束后，所有玩家以玩家的身份，执行lobby {游戏id}以返回大厅

史莱姆需要设置成发光

大部分交互事件都需要设置合适的音效

游戏开始时，在聊天栏输出简短的游戏规则说明

制作时，请用kotlin进行编写，并先将/mnt/d/code/java/projects/mc-dig-wool这个小游戏复制过来作为模板（包括pom等，但别覆盖README），而不是全自己生成代码。

## 插件配置与运行

本项目使用 Kotlin、Paper 26.2 和 MCZJUGameCore 1.5.1。将打包生成的 jar 与 MCZJUGameCore 一起放入服务器 `plugins` 目录，并在 MGC 中为游戏 `mc_backbreaker_slime_trap` 创建房间。房间必须设置 `spawnLocation`，建议将其放在有地面、上方至少两格净空的场地中央；玩家与史莱姆共用此出生点。场地边界需要由地图本身提供。

房间中可调整 `spawnDelaySeconds`（首次出现等待）、`roundSeconds`（每轮爆炸基准时间）、`showExplosionCountdown`（是否显示爆炸倒计时，默认 `true`）、`explosionTimeVarianceSeconds`（爆炸时间随机增减的最大秒数，默认 `0`）、`slimeSpeed`（每 tick 移动格数）、`attachDistance`（附身距离）、`throwDelaySeconds`（可投掷等待）、`attachedExplosionSeconds`（持有史莱姆的爆炸时限 N 秒，默认 `0`，小于等于 `0` 时禁用）、`cumulativeAttachedExplosion`（是否按玩家累计整局持有时间，默认 `true`；关闭后每次附身重新计时）、`throwSpeed`（投掷速度）、`playerSpeed`（玩家初始行走速度）与 `attachedPlayerSpeed`（附身时的行走速度）。行走速度使用 Bukkit 速度值（默认 0.2，配置范围 0 到 1），附身速度不能高于初始速度。每轮爆炸时间会在基准时间上下限内随机取值，最低为 1 秒。史莱姆会随爆炸临近加快闪烁，并播放音符盒提示音；关闭倒计时文字不会关闭这些预警效果。每局接受 3 至 7 人。

使用 `mvn -DskipTests -Dkotlin.compiler.daemon=false -Dkotlin.compiler.execution.strategy=in-process package` 构建。运行时建议验证：正常附身与投掷、倒计时归零时的两种情况、玩家死亡和中途退出后的 5 秒重置、最后一人结算，以及多房间同时运行。

累计计时验证：将 `attachedExplosionSeconds` 设为 `10`、`cumulativeAttachedExplosion` 设为 `true`，并将整轮爆炸时间调长；同一玩家先持有约 4 秒后扔出，再次持有应只剩约 6 秒，其他玩家的额度独立。局内淘汰其他玩家进入下一轮后，该玩家的剩余额度应保留；结束后新开一局应恢复为 10 秒。将累计开关设为 `false` 后，每次附身应重新获得 10 秒；时限设为 `0` 或负数时应禁用持有超时淘汰。

## MGC 1.5.1 统计接入（2026-11-05）

MGC 依赖升级为 `1.5.1`，保持 `provided`，Paper 版本及原有房间 ID 不变。使用 JDK 25 执行 `mvn package`，生成插件位于 `target/`。运行服务器也需要 MGC 1.5.1。

核心自动采集参赛次数、有效游戏时长和符合资格的原版死亡/击杀，本插件不重复递增。适用的自定义淘汰在移除成员/切旁观前报告；结果按游戏实例与玩家 UUID 去重。

新增/接入指标：成功甩出史莱姆次数；最长存活时间（按运行 tick × 50 毫秒）。通过 `/mgc stats mc_backbreaker_slime_trap` 查看（权限 `mgc.mgc`）。自定义值由 MGC 玩家数据管理器在 `player_data/mc_backbreaker_slime_trap_statistics/` 持久化，旧排行榜数据结构保留。除上述明确兼容的历史纪录外，不追溯补算之前的场次和动作。

结算口径：最后存活者胜，其他人负；开局后退出判负但不伪造死亡。史莱姆造成的自定义淘汰报告死亡，原版死亡不重复报告。

语音组：本次没有创建语音组。


验证：本次构建及已有测试结果见工作区 `小游戏总结.md` 的同名升级记录。仍需在 Paper 测试服检查正常结算、平局（若适用）、重复结束、退出/断线、等待取消、运行中断、并发房间、退出后新开另一游戏及重启后的统计持久化。

## 已实现成就（2026-11-05）

插件版本 `26.2-261105`，MGC `1.5.1`。以下成就已注册，使用 `/mgc achievements mc_backbreaker_slime_trap` 查看；核心同时提供原生成就树和持久化。

| 成就 ID | 名称 | 解锁条件 |
| --- | --- | --- |
| `hot_potato` | 烫手山芋 | 同局成功甩出至少 5 次史莱姆，最终获胜 |
| `last_second` | 千钧一发 | 本轮爆炸前最后 1 秒内甩出，爆炸触发后仍存活 |
| `share_the_slime` | 雨露均沾 | 同局自己甩出的史莱姆先后附身至少 3 名不同对手 |
| `untouched` | 不沾锅 | 至少 4 人开局，整局未被附身并最终获胜 |

所有单局状态由游戏实例持有，不跨房间或新局复用。取消和运行中断不发放正常完赛/胜利类成就；已达成的即时技巧类成就不因后来中断而撤销。

运行验收：正常游玩检查上述条件与临界值、取消/中断不误发、退出后新局不继承状态、多房间隔离、重新登录及服务器重启后成就保留。涉及实体/地图清理的安全测试仍应在备份测试服执行，保留其他房间与大厅/入口 NPC，覆盖正常结束、异常中断、初始化失败及停用/重复清理。
